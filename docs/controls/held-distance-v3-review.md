# 작은 물체 놓기 및 보유 거리 제한 검토 — v3

2026-11-01. 사용자 플레이 캡처 3장과 Gallery 소스·실제 Unity 검사를 대조했다.

## 작은 물체를 놓지 못했던 이유와 수정

`ObjectInteraction.ReleaseRestriction`에 제가 이전 수정에서 남겨둔 `localScale.x < MinScale` 거부 조건이 있었다. 운반용 최소 크기와 놓기 제한을 나눴지만 사용자 의도에는 불필요한 제한이었다. 두 프로젝트의 이 조건을 삭제했다. 이제 작다는 이유로 거부하지 않으며, 위치·크기를 바꾸지 않고 Rigidbody 중력·충돌을 복원해 놓는다. 실제 벽 또는 플레이어와 겹치는 경우의 안전 검사는 유지한다.

작게 놓기, 실제 자세/크기 보존, 중력 복원, 다시 잡아 확대하기를 검사했다.

## 현재 거리 계산 순서

1. 잡을 때 크기/거리 비율 `q = grabScale / grabDistance`를 저장한다.
2. 현재 카메라 위치와 운반 방향, 회전을 사용한다. A/D 이동도 현재 카메라 위치로 매 프레임 재계산한다.
3. 물체의 복합 충돌체 전체 화면 실루엣에 광선을 배치한다. 중앙 조준점의 광선 한 개만 사용하지 않는다.
4. 각 광선에서 환경 표면까지의 거리와 물체 뒤쪽 표면의 비율로 허용 깊이를 계산하고, 그중 가장 작은 값을 고른다. 접촉 여유는 0.99를 곱한다.
5. 공간 경계·크기 상한과 대조한 뒤 위치와 크기를 함께 적용한다. 일반 경로의 크기는 `q × depth`, 플레이어 회피가 필요한 경우 별도 축소율을 곱한다.
6. 유한 광선이 놓친 얇은 모서리는 마지막 환경 부피 검사로 보완한다.

거리 Lerp나 A/D 전용 고정 운반 거리가 있는 구조는 아니다. 카메라가 옆으로 이동하면 광선이 기둥에서 벗어나 먼 벽을 만나면서 깊이와 크기가 회복되어야 한다.

## 확인된 보이지 않는 제한

이전 Gallery는 물체의 원래 전시 구역으로 투영과 놓기를 제한했다. 예를 들어 첫 구역은 모든 꼭짓점의 Z가 **13.69m 이하**여야 했다. 실제 문이 열려 있고 다음 구역에 빈 공간이 있어도 이 선을 넘지 못했다. 구역 끝은 13.7 / 26.7 / 39.75 / 53.8m로 코드에 직접 들어 있었다.

이 내부 경계를 두 Gallery 소스에서 제거했다. 물체의 zone은 퍼즐·복귀 분류로 남겨두고, 투영/놓기는 Gallery 전체 외곽과 실제 충돌체로 판단한다. 빈 통로 뒤 Z=22m 벽을 배치한 검사에서, 이전에는 중심 깊이 약12.45m에서 멈췄지만 이제 독립적인 기하 기대값 **19.7982m**까지 도달하고 놓인다.

## 캡처에서 더 구분해야 하는 제한

- 캡처의 `0.81 / 6.25 ≈ 0.1296`, `1.26 / 9.79 ≈ 0.1287`은 표시 반올림을 고려하면 비슷하다. 거리와 크기를 함께 바꾸는 동작은 관찰된다.
- 첫 그림의 크기 상한은 **3.475**다. 캡처의1.26은 그 상한에 도달하지 않았으므로 해당 장면을 크기 상한 때문이라고 설명할 수 없다. 같은 비율에서 크기 상한만의 깊이는 대략27m다.
- 그림 충돌체의 높이는2.8m, 너비는2.4m다. 1.26배면 높이가 약3.53m가 된다. 중앙 뒤쪽에 공간이 보이더라도 하단이 바닥에 먼저 닿으면 그 하단의 광선이 깊이를 제한한다.
- 씬의 베이지색 `First exhibition corridor`는 두께0.22m, 높이4.5m, 길이7.3m인 벽 두 개다. 얇은 기둥처럼 보이는 시점에서도 길게 이어진 충돌체를 고려해야 한다.
- 파란 칸막이는 실제 두께0.38m 충돌체다. 조준점만 문을 통과해도 확대된 그림 가장자리가 칸막이에 닿으면 그림 전체는 통과할 수 없다.

정확한 카메라 좌표·각도와 당시의 제한 광선을 캡처에서 복원할 수는 없다. 따라서 **9.79m를 만든 정확한 collider를 캡처만으로 확정하지 않았다.** 확인·재현된 문제는 보이지 않는 내부 구역 경계이며, 바닥·통로벽·칸막이의 실제 접촉 제한은 정상적으로 남는다.

## 검증 및 실행

정식 Editor의 새 회귀에서 작은 물체 놓기와 열린 통로 너머 먼 벽 배치를 실패→통과로 확인했다. 두 프로젝트의 전체 조작·물리 묶음도 통과했다. 별도 Gallery v3를 정식 Unity6000.3.24f1에서 재빌드하고 실제 Windows/GPU 실행 검사를 통과했다. 로그는 `artifacts/validation/editor-build/contact-v3-*.log` 및 `gallery-v3-*.log`에 있다.

[Gallery v3 실행](../../play-gallery-v3.cmd). 실제 파일은 `builds/windows/gallery-v3/Parallax.exe`다. `play-gallery.cmd`와 `추가판_실행.cmd`도 v3로 연결했다. 기존에 실행 중이던 v2 프로세스의 코드는 바뀌지 않으므로, v3를 별도로 실행해야 한다. 다른 맵은 소스의 작은 물체 놓기 처리를 수정했으며 해당 실행본의 재빌드는 별도다.

재빌드 시 `GalleryPlatformBuild.BuildWindows`의 `-parallaxBuildOutput`에 `builds/windows/gallery-v3/Parallax.exe` 절대 경로를 지정한다. 루트의 일반 build-windows 스크립트 기본 출력은 기존 `builds/windows/gallery`이므로 버전별 실행 경로를 확인한다.
