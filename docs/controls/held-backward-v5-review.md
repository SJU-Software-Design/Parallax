## 코드 원인

GalleryWorld의 `03 · 낮은 전시대`는 `maxScale=3.2`로 제작되어 있었다. 잡을 때 다음 비율을 저장한다.

```text
q = 잡을 때 크기 / 잡을 때 카메라 거리
현재 크기 = q × 현재 거리
크기 상한으로부터의 최대 거리 = 3.2 / q
```

처음 잡기의 비율은 표시값 기준 약 `3.20 / 9.12 = 0.35088`이다. 따라서 뒤로 물러서도 허용 거리가 9.12m로 고정되고, 물체는 카메라와 함께 움직인다. 벽까지 빈 공간이 남아도 크기 상한이 먼저 선택된다.

놓은 뒤 다른 위치에서 다시 잡으면 새 비율을 저장한다. 13.26m와 16.81m에서 3.20이 되는 것은 각각 다른 기준 비율이 저장되었기 때문이다. 상한에 닿기 전에는 실제 표면에 의해 거리가 늘고 크기도 커지므로 사용자가 서로 다른 운반 로직처럼 느꼈다. 잡기 시 비율을 새로 계산하는 것 자체는 현재 보이는 크기를 보존하기 위한 정상적인 원근 규칙이다.

## 실제 재현과 수정

같은 크기의 저상 전시대 충돌체 `(1.25, .45, 1.25)`와 실제 Gallery 어댑터·PhysX 쿼리를 사용했다. 처음 크기 1, 거리 2.85m, `maxScale=3.2`로 놓고 22m 앞에 벽을 만들었다.

- 수정 전: 실제 표면 후보 **17.86111m**인데 `Limiter=Size`, 깊이 **9.12m**, 크기 **3.2**를 선택했다. 기대 동작 검사가 이 이유로 실패했다.
- 수정 후: `Limiter=Surface`, 깊이 **17.86111m**, 크기 **6.267056**을 선택했다.
- 뒤로 2m 이동: 깊이 **19.48499m**, 크기 **6.83684**로 증가하고 벽 쪽 끝점은 기존 접촉 여유 안에서 유지되었다.
- 큰 크기 그대로 놓기, 다시 잡기, 다시 2m 후진 시 거리·크기 증가도 확인했다.

두 프로젝트의 `GalleryProp`이 `IInteractionProp.MaxScale`에 무제한을 반환하도록 수정했다. 기존 직렬화 `maxScale` 데이터는 호환을 위해 보존하며 Gallery 배치에는 사용하지 않는다. 공통 solver의 크기 상한 기능과 다른 스테이지 정책은 그대로다.

이제 Gallery의 최대 배치는 실제 벽·바닥·천장·다른 물체와 외곽 경계로 결정한다. 바닥이나 옆벽이 더 먼저 닿는 경우에는 그 실제 표면이 제한 원인이다. F3 진단 화면으로 확인할 수 있다. 플레이어 겹침 회피·놓기 안전 검사·질량 상한은 유지한다.
